# 开源范围规范

> 本文件定义本仓库**包含什么**、**不包含什么**，以及执行顺序。
> 它是规范，不是执行记录。

## 一、要开源的功能

| 子功能 | 说明 | 剥离难度 |
|---|---|---|
| 排行榜主视图 | 多维度切换的模型排行 | 高（含大量视图与多语言逻辑） |
| 视图维度 | 开源 / 编程 / 性价比 / 最新 / 速度 | 中 |
| 模型详情与对比 | 单项详情、两两对比 | 中 |
| Pareto 前沿提示 | 性价比散点上的前沿线 | 低 |
| 分享卡片 | 生成分享图 | 低 |
| 图表 | ECharts，本地打包 | 低 |
| 采集脚本 | 从上游同步数据 | 中（见 UPSTREAM-TOS.md） |

## 二、技术栈

| 层 | 技术 |
|---|---|
| 后端 | PHP 8.1，无框架，原生 PHP |
| 数据库 | MariaDB 10.6 |
| 前端 | 原生 JS + ECharts（本地打包，非 CDN） |
| 渲染 | PHP 服务端渲染为主 |

## 三、绝对不包含（红线）

- **用户体系**：注册 / 登录 / 会话 / 验证码
- **商业逻辑**：会员定价、支付、订单、返利
- **后台管理端**
- **网络情报相关模块**
- **任何真实密钥或凭据**（上游 API Key 一律走环境变量）
- **上游数据的全量快照**（见 UPSTREAM-TOS.md）
- **基础设施**：Web 服务器配置、部署脚本、备份脚本

## 四、配置约定

```php
<?php
// config/llm_sources.example.php
// 复制为 config/llm_sources.php 后填入自己的 Key；
// 也可以把真实值放在 Web 根之外的文件里，用 getenv() 读取。
return [
    'openrouter_key' => getenv('LLM_OPENROUTER_KEY') ?: '',
    'hf_token'       => getenv('LLM_HF_TOKEN') ?: '',
];
```

**要点**
- 仓库里只允许出现 `*.example.php`
- 所有上游 Key 均为**可选**：没有 Key 时脚本应跳过对应上游而不是报错退出
- `.gitignore` 已排除 `config/*.php`，但保留 `*.example.php`

## 五、数据策略

**只开源代码 + 少量示例数据**。

- `data/`：10–20 条示例模型记录，够看清效果即可
- `data/raw/` 与 `raw-*.json` 已被 `.gitignore` 排除 —— 上游原始快照不进仓库
- 采集脚本默认不启用需要 Key 的上游

## 六、执行顺序

```
阶段 1  文件分类 → 产出「可开源 / 需改造 / 禁止开源」三份清单，等用户确认
阶段 2  代码剥离 → 先做主视图（单维度），再扩到多维度；最后做详情/对比/分享卡
阶段 3  脱敏与模板化 → 建表 SQL 去隐私字段；配置改 example 模式
阶段 4  本地验证【不能省】→ 用 Docker 起干净环境，确认 clone 下来能跑通
阶段 5  法务核查（人工）→ 见 UPSTREAM-TOS.md，逐条确认后再决定是否启用采集脚本
阶段 6  发布 → README 截图、Demo 链接
```

## 七、执行者须知

- **不要**把上游文件整份复制过来，必须逐文件审查
- 不确定是否敏感的内容，**列出来问，不要自行决定**
- 收集脚本涉及第三方条款，**不要自行判断"应该没问题"**
- 提交前用密钥扫描工具（`gitleaks` / `git-secrets`）过一遍
- 本仓库当前是**骨架**：`public/`、`scripts/`、`sql/`、`data/` 均为空
